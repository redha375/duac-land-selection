# التعمير — النسخة الآمنة 3.3 التجريبية

[افتح التطبيق](./index.html) · [ملف إعداد Supabase الآمن](./supabase-secure.sql)

هذه نسخة ويب/PWA جديدة من واجهة DUAC Médéa، مع صلاحيات الفريق التي يفرضها PostgreSQL عبر RLS: المدير يقرأ ويضيف ويعدّل ويحذف ويدير الحسابات؛ العون يقرأ ويضيف ويعدّل ويرفع PDF؛ والمراقب يقرأ السجلات والملفات فقط. هذه الصلاحيات لا تعتمد على دور مخزّن في المتصفح.

## الإعداد اللازم قبل الاستخدام الجماعي

- أنشئ مشروع Supabase جديدًا ومخصصًا لهذا التطبيق؛ لا تشغّل الترحيل على مشروع حالي قبل مراجعة أثر أسماء الجداول وسياسات الوصول.
- نفّذ `supabase-secure.sql` في SQL Editor، ثم أنشئ حسابك من التطبيق، وبعد تأكيده شغّل مقطع التهيئة الأخير داخل الملف من لوحة Supabase، مستبدلًا البريد بعنوان حسابك هناك فقط.
- اربط التطبيق بـ Project URL و `anon` / publishable public key فقط. لا تضع `service_role` أو كلمات مرور أو بيانات دخول في الشفرة أو مستودع GitHub.
- أنشئ الحسابات الأخرى من التطبيق؛ تبدأ موقوفة. سجّل بحساب المدير، افتح «إدارة الصلاحيات»، واختر لكل حساب دوره وحالة تفعيله.
- سجلات الفريق والـPDF لا تُحمّل قبل دخول عضو فعّال. ملفات PDF خاصة وتُفتح بروابط مؤقتة بعد تحقق الخادم. الخريطة تتطلب الإنترنت.

الترحيل لا يُطبّق تلقائيًا على أي خدمة مستضافة، ولا يحتوي هذا النشر على بيانات اعتماد لمشروع Supabase. يجب على مالك المشروع تشغيل SQL وتهيئة أول مدير قبل استعماله. بيانات 3.2 السابقة لا تُرفع أو تُدمج تلقائيًا.

## حدود النسخة

هذه نسخة ويب تجريبية وليست APK. لم تُنشر إعدادات Supabase ولم تُختبر حسابات الأدوار فعليًا على مشروع حي؛ اختبارات المصدر تؤكد قواعد RLS المعتمدة في الملف فقط. لا تستخدم بيانات رسمية أو شخصية حساسة قبل تهيئة مشروع مخصص واختبار الحسابات الثلاثة. إصدار Android الميداني الفارغ 2.3.0 محفوظ دون تغيير.
